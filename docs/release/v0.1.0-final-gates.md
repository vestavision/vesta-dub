## Translation decision

The default translator is the local Firefox Translations `en-tr` model documented in `docs/release/local-translation-model.md`. Google Cloud Translation API v2 remains an optional bring-your-own-key provider. It is not selected automatically.

The P9.1 notes below describe that optional provider.

- REST: `POST https://translation.googleapis.com/language/translate/v2`
- Auth header: `X-Goog-Api-Key` ([API keys](https://cloud.google.com/docs/authentication/api-keys-use))
- v2 accepts API keys. v3 does not ([Cloud Translation authentication](https://cloud.google.com/translate/docs/authentication))
- NMT price, reviewed 2026-10-16: first 500,000 characters per month free as a credit, then $20 per million characters ([pricing](https://cloud.google.com/translate/pricing))
- Body: `{ "q": "<caption>", "target": "tr", "format": "text" }`

DeepL was rejected for V1. Its auth page says not to use a key in client-side or publicly distributed code ([DeepL auth](https://developers.deepl.com/docs/getting-started/auth)). An extension package is client-side software. Undocumented free endpoints were not added.

The implementation was verified with mocked `fetch` in `tests/p9_1_release_blockers.test.ts`. No live request was made.

On the default Local setting, English-caption dubbing does not wait for a key. On the Cloud setting, a missing key stops the session with the setup message and does not speak English. Turkish caption tracks do not need either translator.
